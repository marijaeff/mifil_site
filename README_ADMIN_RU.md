# MiFiL CMS — этапы 1 и 2

Это дополнение к существующему сайту MiFiL. Оно **не меняет 3D-дом и его анимации**, не удаляет проекты, не изменяет Playable Letter и не требует React или другого фреймворка.

## Уже реализовано

- Защищённая страница `/admin/` с входом через Firebase Authentication (Email/Password).
- Проверка реальных прав администратора по документу `cmsAdmins/{uid}` в Firestore. Пользователь **не может назначить себя администратором** из браузера.
- Отдельные документы `siteContent/draft` (только администратор) и `siteContent/public` (читается сайтом).
- Первый **контролируемый импорт** текущего содержимого: 4 проекта, 3 страницы, 16 языков, краткие описания, статусы и надписи «Скоро».
- Редактор названий, ссылок, иконок и статусов существующих 4 проектов.
- Редактор всех существующих переводов, коротких описаний и текстов страниц.
- Черновик, публикация, восстановление черновика из публикации, экспорт JSON-копии.
- Главная и `page.html` читают опубликованные данные из Firestore. Если конфигурация отсутствует или Firestore временно недоступен, **отображаются исходные локальные тексты** из `texts.js` и `assets/`.

## Пока НЕ реализовано

Создание произвольных разделов, новых проектов и страниц, добавление/перемещение блоков, загрузка медиафайлов и CMS для внутреннего лендинга Playable Letter — всё это следующий этап. Четыре физических окна 3D-дома всё ещё закреплены за исходными ID.

## Шаг 1. Создай отдельный проект Firebase

1. Открой https://console.firebase.google.com/ и создай отдельный проект, например `mifil-website`. **Не используй учебную базу Firebase Learning Lab**: MiFiL — отдельное приложение.
2. В Project Overview → Project settings добавь Web App и скопируй его **Firebase Web App configuration**.
3. Открой `firebase/config.js` и замени заглушки на значения из Firebase Console:

```js
export const firebaseConfig = {
  apiKey: 'ключ из Firebase Web App',
  authDomain: 'твой-project-id.firebaseapp.com',
  projectId: 'твой-project-id',
  appId: '1:...:web:...',
};
```

Эти значения — открытые параметры клиентского приложения, а **НЕ секретный admin/service account**. Никогда не публикуй сервисные ключи, закрытые JSON-ключи или пароль администратора.

## Шаг 2. Включи вход и создай администратора

1. Firebase Console → Authentication → Sign-in method → включи **Email/Password** (не обязательно включать Google Sign-in).
2. Authentication → Users → **Add user**. Введи свою электронную почту и пароль.
3. Скопируй **UID** созданного пользователя из списка Users.
4. Firestore Database → Create database (лучше Production mode) → выбери регион. Для отдельного проекта это можно делать независимо от других твоих приложений.
5. Firestore → вкладка Data → **Start collection** `cmsAdmins` → Document ID = точный UID из Authentication → добавь поле `role` (string) со значением `owner` → Save.

Важно: коллекцию `cmsAdmins` создают только вручную через консоль или доверенную серверную среду. Не давай её изменять из приложения.

## Шаг 3. Установи Security Rules

В Firebase Console → Firestore Database → Rules скопируй **всё содержимое** файла `firebase/firestore.rules`, затем нажми **Publish**.

Rules позволяют:

- посетителям читать только `siteContent/public`;
- администратору читать и записывать `siteContent/public` и `siteContent/draft`;
- только владельцу UID читать свой `cmsAdmins/{uid}`;
- никому из браузера не создавать и не изменять `cmsAdmins/{uid}`;
- запрещают доступ ко всем остальным коллекциям.

**Внимание:** эти правила рассчитаны на отдельный Firebase-проект для MiFiL. Если используешь Firestore вместе с другими приложениями, нельзя просто заменить все правила: это заблокирует их коллекции. Требуется аккуратно объединить правила.

Проверь в Rules Playground / Emulator как минимум: анонимный посетитель может прочитать `siteContent/public`, но не `siteContent/draft`; обычный пользователь не может писать; администратор может писать; никто из браузера не может создать `cmsAdmins`.

## Шаг 4. Разреши свой домен для входа

Firebase Console → Authentication → Settings → Authorized domains — добавь домен, на котором будет находиться MiFiL. Для GitHub Pages может понадобиться и домен `username.github.io`, и собственный домен MiFiL (если используется). Используй **HTTPS**. При проверке через localhost добавь `localhost` в разрешённые домены, если он не включён.

## Шаг 5. Обнови файлы сайта

Если скачан патч, скопируй его в корень исходного сайта **с заменой файлов** — сохраняя структуру папок. Не удаляй другие файлы сайта.

Изменённые или новые файлы:

```
index.html                     # Подключён загрузчик Firestore
page.html                      # Подключён загрузчик Firestore
script.js                      # Обновление элементов при загрузке данных
firebase/config.js            # Конфигурация Firebase (заполнить вручную)
firebase/site-content.js      # Публичная загрузка контента
firebase/firestore.rules      # Защита доступа
admin/index.html              # Вход и редактор
admin/admin.css               # Стили панели управления
admin/admin.js                # Логика CMS
README_ADMIN_RU.md            # Эта инструкция
```

Остальные файлы сохраняются без изменений: `texts.js`, `assets/project-teasers.js`, `assets/project-status.js`, `js/house.js`, `playable-letter/`, модели дома и т. д.

**Примечание:** если сайт сейчас работает на GitHub Pages, загрузи изменённые файлы в репозиторий. Не надо запускать сайт двойным кликом по `index.html` как `file://` — для проверки Firebase нужен нормальный сайт HTTPS или локальный веб-сервер.

## Шаг 6. Первый импорт исходного контента

1. Открой `https://ТВОЙ-ДОМЕН/admin/`.
2. Войди под аккаунтом, чей UID ты внесла в `cmsAdmins`.
3. В пустой базе появится кнопка «**Импортировать содержимое сайта**».
4. Нажми её. Содержимое текущих `texts.js`, `project-teasers.js`, `project-status.js` и `MiFiLProjects` будет импортировано сразу в `siteContent/public` и `siteContent/draft`.
5. Переоткрой главную страницу — её вид останется прежним, но опубликованные данные уже будут прочитаны из Firestore.

Импорт использует транзакцию и **откажется перезаписывать уже существующую публикацию**. Если документ `siteContent/public` уже создан, редактор загрузит его, а не предложит повторный импорт.

## Шаг 7. Проверь редактирование

1. Открой «Переводы» → выбери русский язык → например, отредактируй поле `intro`, `worlds` или краткое описание проекта.
2. Нажми «**Сохранить черновик**». На публичном сайте **пока ничего не изменится**.
3. Нажми «**Опубликовать**».
4. Обнови публичную страницу — ты увидишь новый текст.
5. В «Проекты» можно переименовать любой из четырёх проектов или изменить его статус. Перед публикацией статуса «доступен» обязательно проверь ссылку!
6. В «Публикация» можно скачать JSON-копию и восстановить черновик из опубликованной версии.

Сайт не подписан на realtime-обновления: после публикации достаточно обычного обновления страницы. При недоступности сети сайт показывает **локальный резервный контент**, поэтому важно не удалять старые `texts.js` и `assets/*`.

## Данные и ограничения

Firestore хранит одну опубликованную и одну черновую **сборку содержимого** (schemaVersion=1). Для текущих четырёх проектов и 16 языков этого достаточно. Когда будем создавать произвольные разделы и много новых страниц, модель при необходимости будет разделена на отдельные коллекции и документы.

Сайт загружает публичный документ **без входа пользователя**, но возможность записи защищена Firebase Security Rules и документом администратора. Наличие `/admin/` в открытом доступе не является риском само по себе, если правила применены правильно.

В проекте использован Firebase Web SDK 13.4.0 через официальный CDN — для этой версии не нужны npm, сборщик или отдельный сервер.

## Что проверить перед реальной публикацией

- Корректность домена в Firebase Auth и вход в `/admin/`.
- Права чтения/записи Firestore, включая недоступность `draft` для посетителей.
- Внешний вид главной и `page.html` на компьютере и телефоне.
- Поворот и 3D-анимации дома, переход в Playable Letter.
- Сохранение черновика, публикацию и чтение данных после перезагрузки.
- Изменение статуса проекта «Скоро» → «Доступен» (и возврат обратно).

При неполадке с Firebase **не удали** локальные `texts.js` и проектные скрипты: они обеспечивают резервный контент.
